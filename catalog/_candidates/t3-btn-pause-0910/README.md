## 제미나이 왕복에서 실측한 것 (다음 발주에 그대로 쓸 것)

1. **여백을 픽셀 숫자로 주면 막힌다.** 「1024 캔버스에 820x820, 사방 102px 검정 띠」로
   못박은 요청(4번)은 **응답 본문이 통째로 비어서** 왔다 — 재생성해도 같았다.
   숫자를 빼고 **「버튼을 작게 그려서 둘레에 넓은 검정 여백이 보이게」**로 정성적으로 바꾼
   5번만 아무 설명 없이 그대로 지켰다. `margin=0.0 → 0.094`.
2. **여백 지시를 지키겠다는 말은 한 번도 하지 않았다.** 3번 응답은 그 규칙을 언급조차 없이
   "캔버스 비율에 맞추어 잘려나갔던 테두리를 복원했다"고 했다(= 오히려 꽉 채웠다는 뜻).
3. **배경 검정 지시도 자주 무시된다.** 1번은 위는 검정·아래는 흰색, 2번은 전면 흰색,
   3번은 제미나이 스스로 "배경이 흰색 등으로 처리되었을 수 있다"고 적었다. 5번만 순검정.
4. 회수는 **응답 이미지의 다운로드 버튼(사다리 1번) 하나로 전부** 됐다. 스티칭 없음 —
   즉 1번의 위검정/아래흰색은 회수 결함이 아니라 **생성물 그대로**다.
5. 웹 UI 가 **오류 1097 + 턴 롤백**을 두 번 일으켰다. 그 채팅방은 버리고 새 방에서 재발주했다.

## 이 부품에 대해 나중에 알아야 할 것

배포본 `duel-btn-pause.webp`(152x151)가 세 변에서 잘린 이유는 **그림이 잘려서가 아니라
오리는 창이 좁아서**다 — `tentwin/assets/art/incoming/mockup/gm-battle-hud.py` 의
`btn_pause: [30,30,200,200]`(+PAD 20). 원본 목업 `gm-ingame-battle.png`(1536x2750)의
같은 자리에는 **온전한 둥근 테**가 그대로 있다(육안 확인).

다만 그 자리에서 버튼은 약 160x153 px 이라 **해상도는 지금과 같고**(표시 118px 의 dpr3 =
354px 에 여전히 미달), 버튼 오른쪽 아래 테를 보라색 캐릭터의 글로우가 덮고 있다.
그 자리를 어떻게 할지는 «그림을 손보는» 결정이라 사용자 판정이 필요하다.

**지금은 그 판정을 구하지 않는다 — HUD 가 「완성」으로 동결됐기 때문이다.**
동결이 풀릴 때 이 문단부터 읽으면 된다. 그때의 선택지는 둘이다:
- (A) 목업에서 창을 넓혀 다시 오린다 → 잘림은 해결, 해상도는 그대로, 보라색 글로우 처리 판정 필요.
- (B) 5번을 재질 피드백 루프로 고친다 → 「좌상단 흰 유광 타원·크림빛 막대·어두운 겉선
      #86444A 를 ref 그대로」를 다음 요청에 명시. 여백은 **정성적으로** 쓸 것(위 실측 1).
