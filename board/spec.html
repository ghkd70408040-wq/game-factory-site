0. 에셋 한 개의 구조 (피그마 순서로 고정)#

한 에셋 = Frame 하나. 그 안은 아래 층 순서로만 만든다. 층은 각각 따로 만들고 따로 바꾼다. 층을 합쳐 굽는 것은 자산(그림) 프레임에서만, 그때도 어느 층이 구워졌는지 기록한다.

순서피그마 층담는 것규칙
1Shape (Vector path) — 외곽선의 형태실루엣 경로, 코너 반경, 홈·구멍, 마스크. 구조가 여기서 결정된다먼저 그린다. 크기 A/B는 여기서. 내용물 자리(Slot)는 빈 영역으로 남긴다
2Fill — 내부 색단색 / 그라데이션 / 이미지 채움, 불투명도(비침)값은 Variables(틀 세트)에서만. 화면별 임의 값 금지
3Stroke — 외곽선의 색·구조색, 굵기(절대 px), 정렬(inside/center/outside), 안쪽 림(두 번째 Stroke)굵기는 영역별 절대 px(대형 컨테이너 / 소형 제어). 색은 Variables
4EffectDrop shadow(접지), Inner shadow, Blur, 광점(Highlight 레이어), 광택 띠위치·크기는 %·px 규칙으로 크기 무관. 손질감·조각만 자산
5Slot (Nested instance 자리)글자·숫자·아이콘·그림·게이지 채움이 들어갈 자리절대 굽지 않는다. 별도 Frame(Instance)을 참조만
6Auto layout / Constraints프레임의 범위(x·y·w·h %), 정렬, 늘림 규칙, 안전 영역화면 폭 3종(390·430·PC)에서 같은 규칙
7Component / Variant / State원형 지정, 변주 축(역할색·크기·형태), 상태(Default/Pressed/Disabled/Selected)같은 원형에서 Fill·Effect만 다르면 Variant, Shape·Stroke가 다르면 다른 Component

메타(필드명·전체 목록의 정본은 manifest/schema.v2.json $defs/frame — 정본 위계 1. 문서는 이름을 바꿔 적지 않는다):

  • 필수: id · tier(§1 계층) · kind(frame \| preview \| source) · status · impl(code / asset / variant / ambiguous) · hook(교체점 정확히 1: Variable 또는 파일 주소) · consumers[].
  • 구조·층: shape.mask(자산 프레임 필수 — alpha:<파일> 또는 실측 경로. 없으면 그 이미지판에 코드 층 금지, §4.1-1) · shape.alpha_bbox(알파≥128 경계 상자) · shape.cap_px(캡 폭 {l,r,t,b} px — 늘림은 이 밖에서만, §4.1-2) · fill · line · fx · slots[](자리 이름) · slot_safe{<슬롯명>:{coord,x,y,w,h,pct,src}}(슬롯 안전 영역 상자 — 원본에서 잰 글자·배지·아이콘 상자와 모서리 기준 여백, §4.1-3) · layout · bbox{coord, x, y, w, h, pct{x,y,w,h}}.
  • 판정·계보: scope(Variable 훅일 때 실제로 덮여야 하는 규칙 선택자 — 첫 정의 오선택 방지, 0908) · frames(정수, §6-1 무결성) · component(이 Frame이 인스턴스인 엔진 Component — §4.1 원칙 0) · lineage(형제 Component와 통합하지 않는 판정의 근거) · states[] · variants{} · recolorable(Fill·Stroke 가능, Effect 조각 불가).
  • 기록: baked_layers(자산이면 구워진 층 번호 1~4) · lost_layers(구운 것에서 층별로 뽑을 때 잃은 층. 광택이 여기 들어가면 실패, §4.1-5) · preview_png · source(시안 S#) · todo · rejections[](사용자 반려 이력 {date, reason} — 2건이면 §9로).

2. Variables / Modes (값의 유일 출처)#

  • Primitive: 색·불투명도·굵기·반경·그림자 원시값.
  • Semantic(Mode): 재질 세트. 최소 둘 — Mode A(모달 컨테이너) / Mode B(모달 밖 인터페이스). 게임마다 값은 다르지만 슬롯 이름은 같다: face, alpha, rim, outline, gloss, contact.
  • Component token: 부품이 Semantic을 참조. 부품이 Primitive를 직접 쓰면 위반.
  • 파일: engine.css(층·수식·토글, 이관) / theme-<game>.css(값, 종속). 매니페스트도 스키마(이관)와 인스턴스 값(종속) 분리.

3. 재질 Component (T2·T3 공통, 크기 무관)#

  • 입력 = Shape + 크기 + Mode. 출력 = Fill·Stroke·Effect가 규칙대로 입혀진 Instance.
  • 규칙: Stroke 굵기·림 = 절대 px(영역 A/B). 광점 = 좌상 코너에서 w·h의 %·높이의 % 크기. 접지 = 아래 오프셋 px·흐림 px·α.
  • 확정 = 재질 시험판(Shape 4종 × 크기 3종 한 장, 승인 1회). 이후 전 Instance 자동.

4. 판정 규칙 (code / asset / ambiguous / variant)#

  • 규칙 기하(판·캡슐·막대·눈금·알약·링·광택·접지·외곽선) = code.
  • 조각·손그림·장식 접합부·캐릭터·삽화 = asset(발주). 발주서는 대상 Frame·Slot·캔버스·2판(흑/백)·팔레트·레퍼런스·글자 금지·용량 상한을 고정 칸으로.
  • ambiguous = code와 발주를 동시에 준비, 관문(시안 크롭 1배율 나란히 + 수치)에서 지는 쪽 폐기.
  • 같은 원형에서 Fill·Effect·State만 다르면 variant(자산 아님).

4.1 이미지판(자산 프레임) 작업 기준 (0908 신설)#

원칙 0 — 부품을 먼저 개념화한다. 이미지를 쓰든 코드로 그리든, 그 부품(버튼·판·캡슐…)의 Component 정의(Shape · Stroke · Fill · Effect · Slot 안전 상자 · State · Variant)가 먼저 엔진·매니페스트에 있어야 한다. 이미지판은 그 Component의 Fill/Effect 층의 한 구현일 뿐이며 Shape에 잘려 들어간다. 이미지가 형태를 정하게 두고 코드 층을 위에 얹는 순간 모서리·슬롯을 아무것도 모르게 된다(0908 그림 버튼 4차 반려의 근본 원인).
  1. 이미지판도 실루엣부터 — 자산 프레임은 알파 기반 마스크(또는 실측 경로)를 함께 등재한다(§0 메타 mask). 위에 얹는 코드 층(채움·광택·슬롯)은 마스크 안에서만. 마스크 없는 이미지판에 코드 층 금지.
  2. 모서리는 늘리지 않음 — 늘림 구간은 중앙 직선부만. 캡 폭(좌·우·상·하)을 실측 px로 등재한다(9슬라이스 코너 px와 같은 칸).
  3. 슬롯 안전 영역 실측 — 원본에서 글자·배지·아이콘 상자와 모서리 기준 여백을 재 슬롯 좌표로 기록한다(§0 메타 slot_safe). 슬롯 요소는 그 상자 안에서만 놓이고, 판 overflow로 잘리는 것 금지.
  4. 원본 겹침 관문 — 조립 결과를 구운 원본 위에 300% 겹쳐 차분 픽셀로 판정한다. 항목 고정: 모서리 4곳 · 겉선 굵기 · 광택 유무 · 슬롯 위치 · 크기 · 겉선 · 서체. 잉크 상자 크기만 잰 것은 실측으로 인정하지 않는다. 도구 tools/measure/overlay-check.py(0908 커밋 0a1e527 — 없는 환경에서는 tools/kit-shot.mjs --scale 4 크롭 + 수동 차분으로 같은 항목을 채운다). 산출은 OVERLAY.jpg(300% 겹침 시트) + overlay.json, FAIL 하나라도 있으면 exit 1.
  5. 구운 것에서 뽑을 때는 층별로 — 판 · 광택 · 글자를 따로 뽑고 잃은 층을 기록한다(§0 메타 lost_layers). 광택이 걷히면 실패 → 재추출 또는 발주(§4 asset 레인).
  6. 글자는 폰트를 원본 레터링에 겹쳐 굵기·둥글기 차분으로 고른다. 크기는 높이 + 폭 둘 다, 겉선·그림자는 300% 실측. 맞는 폰트가 없으면 레터링 자산 발주(글자를 눈대중으로 키우지 않는다).
  7. 판 결함은 수리보다 원본 재추출 우선. 수리했으면 원본 캡과 차분 0을 증명한다.
  8. 지휘자 관문 — 사용자에게 보내기 전 지휘자가 300% 크롭(모서리 · 슬롯 · 글자)을 직접 본다. 에이전트 보고·스크립트 PASS는 이 눈을 대신하지 못한다(§6-8). 순서 고정 세 걸음: ① python tools/measure/judge-precheck.py --img <시트> --ref <원본> --out <폴더> → ② <폴더>/PRECHECK.jpg(600% 크롭)를 Read 로 직접 연다 → ③ python tools/measure/judge-precheck.py --mark --out <폴더> 로 열람 표식을 남긴다. 표식이 없으면 scratchpad/ 아래 jpg·png 전송이 tools/hooks/guard-send.py 에서 exit 2 다. 표식은 「만들고 열었다」는 행위의 흔적이지 눈 자체가 아니므로, 손으로 만들어 우회하는 것은 위반을 스스로 적는 일이다.
  9. 이미지판 재구성은 층으로만 (0908 4차 반려 근거) — 구운 판에서 글자·배지를 걷을 때 행 보간·구역 편평화·중앙값 채움 같은 픽셀 재구성 금지. 허용되는 방법은 둘뿐: ⓐ 겉선 링(원본 알파 경계 + 겉선 폭 + 안전 2px)은 픽셀 그대로 보존하고 안쪽 마스크에만 깨끗한 열에서 표본한 행 그라데를 새로 채운다(경계는 채움이 균일한 직선부 안에서만, 양쪽 색차 <3/255 증명) ⓑ 판 전체를 코드 Shape(실측 반경·겉선·그라데·광택)로 렌더하고 손질감(광점 블롭)만 자산. 어느 쪽이든 원본 겹침 차분은 글자·배지 구역 안에만 남아야 한다(링·캡·광점 0). 슬롯 추출(배지 등)은 알파 경계 + 여백으로 잘라 겉선이 잘리지 않게 하고, 숫자+글자 슬롯은 원본 간격을 실측해 고정 폭·자간으로 재현한다.
